💻 Используемые технологии

🔄 Маршрутизация (Front Controller)

Маршрутизация реализована через .htaccess (Apache mod_rewrite) и единую точку входа. Все запросы к API перенаправляются в api/index.php, который обрабатывает маршруты.

.htaccess (файл маршрутизации)

RewriteEngine On
RewriteBase /proj/

# Перенаправление всех API запросов в api/index.php
RewriteCond %{REQUEST_FILENAME} !-f
RewriteCond %{REQUEST_FILENAME} !-d
RewriteRule ^api/(.*)$ api/index.php [QSA,L]

# Если не API и не статический файл, отправляем на fallback.php
RewriteCond %{REQUEST_FILENAME} !-f
RewriteCond %{REQUEST_FILENAME} !-d
RewriteRule ^(.*)$ fallback.php [QSA,L]

Как работает маршрутизация:

Запрос пользователя
        │
        ▼
    .htaccess (mod_rewrite)
        │
        ├── /proj/api/* → api/index.php (REST API)
        │
        ├── /proj/*.css, *.js, *.jpg → статические файлы (прямая отдача)
        │
        └── все остальные запросы → fallback.php (при отключённом JS)

📡 REST API

API реализован в соответствии с принципами REST. Единая точка входа — /proj/api/index.php. Все данные передаются в формате JSON.

Доступные эндпоинты:

POST /proj/api/applications — создание новой анкеты 
{
    "fullname": "Иван Петров",
    "email": "ivan@example.com",
    "phone": "+7 999 123-45-67",
    "biography": "Люблю программировать",
    "contract_agreed": true,
    "languages": ["PHP", "JavaScript"]
}
Ответ: 
{
    "success": true,
    "id": 123,
    "login": "ivanpetrov456",
    "password": "aB4#kL9@mN",
    "profile_url": "/proj/api/applications/123"
}
PUT /proj/api/applications/{id} — обновление анкеты (требует авторизации)
GET /proj/api/applications/{id} — получение данных анкеты
POST /proj/api/auth/login — авторизация 
{
    "login": "ivanpetrov456",
    "password": "aB4#kL9@mN"
}
GET /proj/api/auth/check — проверка статуса авторизации
POST /proj/api/auth/logout — выход из системы
✅ Особенности API:
  • Все ответы в формате JSON
  • Авторизация через сессии (credentials: 'include')
  • CORS-заголовки для поддержки кросс-доменных запросов
  • Валидация данных через общий класс Validator
  • Защита от SQL-инъекций (PDO + подготовленные выражения)

Генерация логина и пароля

// Генерация логина из ФИО
function generateLogin($fullname) {
    $cleanName = preg_replace('/[^a-zA-Zа-яА-ЯёЁ]/u', '', $fullname);
    $cleanName = substr($cleanName, 0, 15);
    return strtolower($cleanName) . rand(100, 999);
}

// Генерация случайного пароля
function generatePassword($length = 10) {
    $chars = 'abcdefghijklmnopqrstuvwxyzABCDEFGHIJKLMNOPQRSTUVWXYZ0123456789!@#$%';
    return substr(str_shuffle($chars), 0, $length);
}

🎨 Frontend (JavaScript)

Основные функции newjavascript.js:

  • checkAuth() — проверка авторизации через API
  • submitViaAPI() — отправка формы через Fetch API
  • doLogin() / doLogout() — вход и выход из системы
  • showLoginForm() — модальное окно входа
  • showCredentials() — отображение логина/пароля после регистрации
  • updateAuthButtons() — динамическое обновление кнопок авторизации
  • alwaysFirst() — сохранение оригинальной функциональности select

Обработка формы (AJAX)

form.addEventListener('submit', async function(event) {
    event.preventDefault();  // Отменяем стандартную отправку
    
    const formData = getFormData();
    const isUpdate = currentUser !== null;
    
    await submitViaAPI(formData, isUpdate);
});

Fallback (при отключённом JavaScript)

Если в браузере пользователя отключён JavaScript, форма отправляется обычным POST-запросом на fallback.php, который обрабатывает данные и показывает результат. Таким образом, сайт работает в любом случае.

✅ Progressive Enhancement: Сайт работает при включённом JS (AJAX) и при отключённом (обычная отправка формы).

🗄️ Структура базы данных

-- Таблица заявок
applications (
    id INT UNSIGNED AUTO_INCREMENT PRIMARY KEY,
    fullname VARCHAR(150) NOT NULL,
    phone VARCHAR(50) NULL,
    email VARCHAR(100) NOT NULL,
    birthdate DATE NULL,
    gender ENUM('male', 'female', 'other', 'unspecified'),
    biography TEXT NULL,
    contract_agreed TINYINT(1) NOT NULL,
    user_id INT UNSIGNED NULL,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
)

-- Таблица языков программирования
programming_languages (
    id INT UNSIGNED AUTO_INCREMENT PRIMARY KEY,
    name VARCHAR(50) NOT NULL UNIQUE
)

-- Связь many-to-many
application_languages (
    application_id INT UNSIGNED NOT NULL,
    language_id INT UNSIGNED NOT NULL,
    PRIMARY KEY (application_id, language_id),
    FOREIGN KEY (application_id) REFERENCES applications(id) ON DELETE CASCADE,
    FOREIGN KEY (language_id) REFERENCES programming_languages(id) ON DELETE CASCADE
)

-- Таблица пользователей (логины и пароли)
users (
    id INT UNSIGNED AUTO_INCREMENT PRIMARY KEY,
    login VARCHAR(50) NOT NULL UNIQUE,
    password_hash VARCHAR(255) NOT NULL,
    application_id INT UNSIGNED NOT NULL,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    FOREIGN KEY (application_id) REFERENCES applications(id) ON DELETE CASCADE
)
